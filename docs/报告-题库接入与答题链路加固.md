| 项 | 结论 |
|---|---|

### 1.2 缺口（本报告要补的）

1. **没有题数对账**：只有"答案全 high"（质量门槛），没有"处理过的题数 == 页面题数"（覆盖门槛）
2. **提交后没有回查闭环**：提交完就认为成功，学习通侧没有回查列表确认
3. **没有 miss 黑名单**：查过的失败题下次还会再查
4. **缓存不跨会话**：重跑同一份作业时前面的题要重新问 AI
5. **没有题库通道**

## 2. 题库接入方案

### 2.1 接口契约（本机实测，2026-11-07）

服务**当前在线**：`tk.wanjuantiku.com` 与 `proxy.tk.wanjuantiku.com` 都返回 `{"status":"t"}`（第三个 host `scriptcat.cn` 连不通，可不接）。

| # | 方法 | 路径 | 作用 | 鉴权 |
|---|---|---|---|---|
| 1 | GET | `api/status?version=` | 探活（`status:"t"`） | 不要 |
| 2 | GET | `api/checkLeft?token=` | 余额（**`data:-1` = 未激活**） | 要 |
| 3 | PUT | `api/register` | 绑定 `{token, md5(token)}` | 要 |
| 4 | **POST** | `api/query?token=&version=` | **查题** | 要 |

查题 form 字段（7 个 + 1 可选）：

```
tm          题干（DOM innerHTML 原文即可，见 §3）
answernum   填空空数（非填空传 0）
type        0 单选 / 1 多选 / 2 填空 / 3 判断
wid / cid   作业 id / 课程 id（提高命中率）
options     选项文本 JSON 数组（去掉 "A " 前缀）
ai          1=题库 miss 后让题库侧 AI 补答；0=纯题库（建议先 0）
coursename  课程名（提高命中率）
```

响应：

```jsonc
{"code":1,"data":"B","left":87}              // 单选
{"code":1,"data":"A,C","left":86}            // 多选
{"code":1,"data":"答一#!#答二","left":85}     // 多空填空
{"code":0,"msg":"题库还未激活或不存在，请先充值"}
```

**陷阱（实测/文档均有）**：
- `code` 只有 `1` 算成功，`code:"1"`（字符串）也算成功 → 用 `Number(code) === 1` 判
- 余额字段名不一致：`query` 用 `left`，`checkLeft` 用 **`data`**
- `msg` 里可能带 HTML（充值链接）→ **不要直接插进 DOM**
- `left < 1` 要暂停并提示充值

成本与节奏：**0.002 元/题**（10 元档 5000 次）；上游脚本节流 2–3 s/题（反风控），20 题 ≈ 50 s ≈ 0.04 元。

Token：32 位 `[0-9a-z]`，**即身份 + 余额**，禁止写进日志/仓库。

### 2.2 主链路（建议）

```
[1] 取题（现有 extractQuestions）
      ↓ 题干原文 + 题型 + 选项 + wid/cid/课程名
[2] 查本地缓存（§5.4）→ 命中即用
      ↓ 未命中
[3] 查 miss 黑名单（§5.4）→ 已拉黑则直接进待人工，不再查
      ↓ 未拉黑
[4] POST api/query（节流 2–3 s）
      ↓ code=1
[5] 答案合法性校验（必须在本次选项里能定位到）
      ↓
[6] 填答案（现有 selectOptions / fillEssayAnswer）
      ↓
[7] 保存 → 题数对账 → 提交 → 回查列表（§5.1 §5.2）
      ↓ 任何一步不满足
[8] 转待审 / 暂停（绝不带缺口提交）
```

**兜底顺序**：缓存 → 题库 → AI（现有 `solveOne`）→ 待人工。

### 2.3 三条必须加的护栏

1. **命中不等于可信**：题库答案可能题号错位或选项顺序不同 → 必须做"答案落在本次选项集合内"的定位校验，定位不到就按 miss 处理
2. **题数覆盖**：题库返回 8 条、页面 10 题 → **不提交**（§5.1）
3. **失败必须降级**：`NO_QUOTA` / `PAUSED` / `NO_HOST` / `EMPTY` 一律回落 AI，不能让整份作业卡死；同时计入 miss 清单

### 2.4 适用范围（重要，别搞错平台）

| 平台 | 题干可取性 | 题库可用 |
|---|---|---|
| **学习通章节测验/作业** | 可取（错字串，见 §3） | ✅ |
| **U校园** | 可取（真文本） | ✅ 且更准（不需要错字匹配） |
| 智慧树 | 待验证 | 未知 |

## 3. 关键实测：学习通题干不是乱码

这是决定"题库能不能用在本题"的前提，我实测过：

```
留档题目 445 条，共 13 374 个字符
私有区(PUA, U+E000–U+F8FF) 字符 = 0（0.00%）
「是什么？」= U+662F U+4EC0 U+4E48 U+FF1F
  → 出现在 3 个不同作业、2 门不同课程里，码点完全一致
「的」U+7684 出现在 163/445 条题目里
```

**结论**：超星用的是**同形字替换**——DOM 里是合法汉字（码点正常），页面用自定义字体把字形换掉。**同一字永远映射成同一个错字，跨作业、跨课程一致。**

**对实现的影响**：

1. 题库可以直接用 `innerHTML` 原文匹配（上游脚本就是这样做的，从不还原字形）
2. 本地缓存/黑名单的键，用**错字串**即可，**不需要建字体映射表**
3. 现有"只能截图问 AI"的注释**对部分页面成立、对这批数据不成立**——实现时不要假设题干一定不可读，先尝试读文本，读不到再截图

## 4. 【重点】除取答案之外，值得实现的部分

以下 7 条按价值排序。每条给出：机制 → 为什么值 → 落点 → 验收标准。

### 4.1 题数对账闸门（价值最高）

**机制**

```
needsReview = !(total > 0 && started && completed && !failed && 已答指纹数 === total)
```

只有"页面题数 == 成功作答题数"才允许自动提交；否则**保存后暂停**，等人工核对。

**为什么值**：这是"敢不敢自动提交"的唯一决策点。绝大多数同类工具死在这里——要么全自动提交（错题、空题也交），要么全人工。宁可少提交，不可带缺口提交。

**落点**：`src/chaoxing/quizrun.mjs` 的主循环结束后、提交前。

**指纹算法（可直接抄）**

```
FNV-1a ⊕ djb2 + 长度 → "a>>>0:b>>>0:len"
```

双哈希抗碰撞 + 可去重（同一题重复记录只算一次）。

**验收**：构造一个"页面 10 题、只答出 8 题"的场景，断言 `needsReview === true` 且**没有任何提交请求发出**。

### 4.2 提交的三道闸

| 闸 | 规则 | 我们现状 |
|---|---|---|
| 确认窗超时 | 提交确认框 45 s 内没闭合 → 暂停，**不重试** | 有确认框处理，无硬超时 |
| 不重复提交 | 进入 `submitting` 后任何异常 → **只回查，绝不发第二次提交** | 有 `submissionPending`，但没显式禁止 |
| 回查才算成功 | 回查列表 `completion === "completed"` 才置 `submitted`；否则 `paused` | 学习通侧没有回查闭环 |

**关键原则**：**不看提交接口的返回值**，只有列表状态可信（学习通提交接口返回跳转或空响应）。

**落点**：`src/chaoxing/submit-control.mjs` + `quizrun.mjs` 提交分支。

**验收**：mock 一个"提交后列表仍是 pending"的响应，断言最终状态是 `paused` 且**只发过一次提交**。

### 4.3 失败矩阵（9 条归因）

| 环节 | 失败 | 归因 | 处置 |
|---|---|---|---|
| 取题 | 不支持的题型 | 题型不在 0–3（图片/编程/听力题） | 跳过该题，最终 `needsReview` |
| 取题 | 无法获取题目信息 | 填空题缺题目 id | 跳过 |
| 查题 | 未找到答案 | `code:0` / `data` 空 | 记 miss，继续下一题 |
| 查题 | 题库错误 | `code !== 1` | 暂停（token 未激活/服务异常） |
| 查题 | 次数不足 | `left < 1` | 暂停 + 提示充值，充值后轮询恢复 |
| 查题 | 所有 host 不可用 | 探活全失败 | 暂停，提示换网络 |
| 填答 | 匹配不到选项 | 答案定位失败 | 该题不计入指纹 |
| 保存 | 无"保存成功"回执 | 45 s 超时 | 暂停，不进入提交 |
| 提交 | 回查非 completed | 平台未确认 | 暂停，禁止重提 |

**落点**：扩 `src/failure-policy.mjs` 的归因表（现有只有"真失败/环境性失败"两大类）。

**验收**：上表 9 条各一个单测，断言归因与处置。

### 4.4 阈值总表（可直接作为默认值）

| 项 | 值 |
|---|---|
| 题库查询节流 | 2–3 s/题（反风控） |
| 保存确认窗口 | 45 s |
| 开始作答确认窗口 | 120 s |
| 无进度超时 | 5 min |
| 队列上限 | 20 份/轮 |
| 题数上限 | 1000 |
| 指纹上限 | 1000（超出判 failed） |

**验收**：常量集中定义 + 一处引用，测试断言默认值不被写成 0/负。

### 4.5 miss 黑名单（这是我方数据支撑的功能）

**实测依据**：445 条留档里 **18 条无答案 + 50 条低置信 = 68 条（15%）** 属于"查了也没结果"的类型。接题库后它们会**被反复扣费**（查 5 次扣 5 次，仍无答案）。

**机制**

| 字段 | 说明 |
|---|---|
| 键 | `归一化题干(前120字) + 题型 + 排序后选项文本` |
| `attempts` | 查询次数（题库/AI 各计一次） |
| `lastError` | `NO_QUOTA` / `EMPTY` / `PAUSED` / `low-confidence` |
| 拉黑阈值 | `attempts >= 3` → 标记 `blocked`，之后**直接跳过查询**，进待人工清单 |
| 恢复 | 用户手点"重试此题"时清零 |

**注意**：键**必须包含排序后的选项文本**——只按题干做键，选项顺序一变答案就错位。

**验收**：同一题三连 miss 后，第 4 次不再发出查询请求（mock 断言请求计数不变）。

### 4.6 跨会话答案缓存（不是省钱，是提速 + 抗故障）

**实测结论（重要，别抱错期待）**：445 条留档按「题干+选项+题型」去重后**仍是 445 条，重复率 0.0%**。说明**跨作业命中率极低**。

所以缓存的定位应当收窄为：

| 场景 | 价值 |
|---|---|
| **重跑同一份作业**（最高频：失败重跑/断点续跑） | 极高：0 ms vs 35 s/题，且题库/AI 都挂了也能跑完 |
| 跨作业/跨学期命中 | 接近 0（数据证明） |

**做法**：把现有 `reusable`（只在当前作业内）的**作用域扩到跨会话持久化**，键同 §4.5。

**命中校验**：缓存答案必须能在本次选项里定位，定位不到 → 当 miss。

**验收**：同一份作业跑两遍，第二遍不再产生任何题库/AI 请求。

### 4.7 作业可做性判定（状态词表）

21 个状态词（未交/已交/待完成/未完成/已完成/已互评/未提交/已提交/待提交/待批阅/已批阅/已作答/未作答/未开始/进行中/已结束/已截止/已过期/待做/待考）。

归类规则：

```
含「已完成/已交/已提交/已批阅/已作答」 → completed
含「已结束/已截止/已过期」            → expired
含「未交/待完成/未提交/未作答/进行中/待做/待考」→ pending（若截止时间已过则降级 expired）
其余                                  → unknown，**不允许开始**
```

**关键**：`unknown` 不允许开始——防止误判把已交作业重做。

**验收**：21 个词各一条断言；未知词断言 `unknown` 且拒绝开始。

## 5. 明确不做（省得下一个 AI 走弯路）

| 不做 | 理由 |
|---|---|
| **字体映射表 / 字形还原** | 题库直发错字串即可匹配（§3），建映射表是纯浪费 |
| **跨作业大题库** | 实测重复率 0.0%，维护成本不值 |
| **OCR** | 比截图问 AI 更慢更脆 |
| **签到相关一切** | 与本题无关；且端点表不在本次交付物里 |
| **UA 伪装 / 假定位 / 假活体** | 硬顶式反检测，与"真实作答"原则冲突 |
| **碰考试页** | 上游明确排除 25 条考试路径，保持这条边界 |

## 6. 风险与边界

| 风险 | 事实 | 缓解 |
|---|---|---|
| 第三方依赖 | 题库会停服/换域名（本次实测发现它把脚本地址换到了 greasyfork.cn） | 三 host 探测 + 失败降级到 AI + 缓存兜底 |
| 外发 | 每次查题发出：题干原文 + 课程名 + 作业 id | U校园 风险低；学习通作业题若带姓名/学号需评估 |
| token 泄露 | 32 位串即余额凭证 | 只存本地配置，不进日志、不进仓库 |
| 命中率未知 | 宣称 99%，无真 token 未验证 | **接入前先拿真 token 抽测 100 题** |
| class 名脆弱 | 上游最脆的一环是 `.questionLi` / `.fontLabel` | 我方用截图/DOM 双路，但引入题库后新增了"题干取不到"这一失败点，需进失败矩阵 |
| 重复提交 | 最坏情况是覆盖已交作业 | §4.2 三道闸 |

## 7. 验收清单（可逐条勾）

1. `api/status` 探活成功；三 host 依次尝试，全失败时降级到 AI 且不中断任务
2. `checkLeft` 能读余额；`left < 1` 时暂停并提示，不继续消耗
3. 单题查询成功：`code=1` → 答案规范化（单/多/判断/填空四种形态）
4. 答案定位校验：答案不在本次选项内 → 判 miss，不填
5. 题数对账：8/10 题 → `needsReview`，**零提交请求**
6. 保存失败/无回执 → 暂停，不进入提交
7. 提交后回查非 `completed` → `paused`，**只发过一次提交**
8. miss 黑名单：同题 3 连 miss 后不再发请求
9. 缓存：同一份作业跑两遍，第二遍零请求
10. 状态词表：21 词归类正确，`unknown` 拒绝开始
11. 离线回归：以上 1–10 全部可在 mock 下跑通（不依赖真实账号与真 token）

## 8. 待确认（挡在实现之前的 3 件事）

1. **是否购买 token**：没有 token 只能验证到"服务在线"，命中率与答案质量无法评估（建议先抽测 100 题，成本约 0.2 元）
2. **`ai` 字段策略**：`ai=0`（纯题库）还是 `ai=1`（题库 miss 后题库侧 AI 补答）——后者可能产生额外计费，未验证
3. **适用范围**：先只接 U校园（真文本，最稳），还是一并接学习通（错字串，需实测命中率）
