# 豆包验证续传与辅助字体回归

## 已确认的两个阻断点

- 安装版日志显示：前面的草稿可以恢复填写，当前题成功发送，但随后回答关联失效。只读核对时，网页上已有该题的完整回答，不能将此故障归为发送失败。
- 独立窗口仅发送一张中性红色方块图。人工完成验证后，捕获到 `/chat/completion` 上仅携带 `block_type:10052` 的控制消息。旧观察器将所有不含本次标记的请求都当作其他提问，导致 `superseded-request`；回答出现后该状态仍不解除。
- 当前题的解码字体实际已加载，失败的是只覆盖 U+2018、U+2019、U+201C、U+201D 的引号辅助字体。旧检查将其作为题干未就绪，并由字体警告禁止回填。

## 修复范围

- 验证控制消息既不确认发送，也不使当前提问失效。仍拒绝真正的新提问、历史回答和错误回执。
- 仅当已知引号字体的全部声明都严格限于上述四个标点时，允许按系统回退字体检查；其他字体仍需要成功加载。没有更改平台网页或删除字体。
- 日志分别记录关联失效原因，避免把所有失效都写成“检测到其他提问”。

## 本轮验证

- 实际网页：同一中性图的已有回答由完整 `askWebImage` 模块成功恢复读取。过程中拦截并计数发送接口，额外请求为 0；未处理课程题目。
- 请求回执单测与浏览器重放：验证续传不使原回答失效；真正的另一个提问仍会阻断。
- 真实字体网络恢复：原始 URL、签名和字重保留，连续三次生成 PNG；引号辅助字体失败不产生待审警告；题干字体失败和不限范围的同名字体仍受保护。
- 截图超时、停止语义、虚拟历史重复答案及逐题恢复回归通过。实际测验执行器保留已答草稿，仅重试失败题，模拟提交次数为 0。
