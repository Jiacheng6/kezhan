# 智慧树登录来源恢复诊断

状态：0.6.2 发布后的源码修复，未修改安装版、未打包、未上传。用户在独立窗口登录后，已完成两次正常退出和同目录冷启动的真实网站验收。

## 已核实

- 安装版当前为 0.6.2，启动记录显示加密会话恢复执行成功，但智慧树页面仍返回登录中心。
- 只读检查发现，部分智慧树登录 Cookie 在恢复后成为 HTTP / 80 来源；网站正常 HTTPS 设置的同类 Cookie 是 HTTPS / 443 来源。`secure` 是发送限制，不能单独用于推断设置来源。
- 更新前的加密备份曾有非空登录票据，当前登录页对应票据已为空。仅凭这点尚不能排除平台会话过期、其他设备登录等原因，也不能宣称来源修复已经解决所有掉线。

## 修改

- 恢复智慧树 Cookie 时使用网站实际支持的 HTTPS 来源，包括网站没有标记 `Secure` 的 Cookie。
- 不修改原 `Secure`、`HttpOnly`、`SameSite`、有效期或会话类型；不覆盖原生存储中较新的登录。
- 不从旧备份强行恢复已退出或失效的票据，不保存账号密码。

## 回归

- `test-browser-session.mjs`：恢复顺序、较新原生登录保护、加密保存与智慧树 HTTPS 恢复属性。
- `test-browser-session-origin.mjs`：真实 Electron 引擎，虚构 Cookie、`about:blank`，复现旧逻辑的 HTTP / 80 来源并核实修复后为 HTTPS / 443。保持原会话类型及安全标记，零网站请求。

## 真实网站冷启动验收

- 用户在保留的独立验收数据目录中完成智慧树登录，正常进入学堂，读取到两门课程。
- 通过软件自己的关闭确认选择退出，等待桌面进程正常结束；安装版始终未关闭、未修改。
- 修复后的源码使用同一数据目录冷启动，通过正常智慧树入口直接进入学堂，两门课程可读取，不需要重新登录。
- 再做一次正常退出、同目录冷启动和正常入口核对，结果相同。
- 两轮均确认关键 Cookie 仍为 HTTPS / 443 来源，未改变其原来的会话类型及安全标记，没有为空的关键票据。
- 没有启动课程、播放视频或提交作业。最终独立验收窗口与登录目录保留。

以上证明本轮两次冷启动能保留有效登录；尚未完成长时间间隔后的留存测试，也不承诺平台会话永不过期。网站主动过期、退出登录或要求验证时仍需本人处理。
