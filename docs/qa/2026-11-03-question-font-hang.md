# 题目字体阻塞与截图恢复

## 原因

`shootQuestion` 在有总字体预算的外层循环里，仍于一次 `evaluate` 中等待 `document.fonts.load()`。字体网络请求挂起时，页面读取上限先到，循环来不及判定恢复，直接报“检查题目字体”超时。增加恢复次数无法覆盖这个分支。

旧恢复代码还以资源计时中的第一个疑似失败 URL 恢复不同字体，没有家族/字重对应关系；零传输大小也不能证明资源失败（缓存和跨域限制都可能出现这个值）。单纯添加一个 loaded FontFace 后，原 CSS FontFace 的 error 状态仍会使 `fonts.check()` 返回 false。

## 改动

- 新增 `src/chaoxing/question-fonts.mjs`。页面侧只同步检查并触发后台加载，等待预算和中止由外层轮询持有。
- 针对长期 pending 进入最多三次恢复；预算耗尽明确返回字体阶段错误，不再先被未结束的加载 Promise 拦截。
- 只从题目使用字体对应的可访问 `@font-face` 读取原地址，保留字重、样式和字符范围，保持原签名查询参数；跨域 CSS 不可读时不猜来源。
- 以 `cache: reload` 请求原地址并限时，校验下载字体后替换该规则的资源，解除旧 error 状态。已加载的正常字体不会反复下载。
- 未能恢复时保留已有安全阀：严格调用不生成不明图片；带警告草稿不自动填入或提交。未改自动提交策略。

## 验证

- `test-question-font-recovery.mjs`：真实浏览器中两种字体先返回503，再按正确地址恢复，核对家族/字重和签名参数；恢复后连续三次截图。
- `test-question-capture.mjs`：不相关字体挂起不阻塞题面；题面字体挂起能进入恢复并按总预算结束；停止立即生效；成像接口挂起后换独立会话恢复一次。
- `test-font-recovery.mjs`：10 项判定测试；`test-self-heal.mjs`：51 项。
- `test-quiz-partial-retry.mjs`：前三题中第三题失败，前两题已落盘；重开后只重试第三题、回填全部草稿，零提交。
