# 0.5.15 讨论草稿功能验收

## 行为

- 默认关闭；开启“生成讨论草稿”并重新扫描课程后，章节内的讨论可以独立选择。
- 仅处理选中的讨论。优先统计相同、近似内容，按独立作者去重，复制出现次数最多的一组中的原文；点赞与回复数量不影响排序。
- 相似度分组保留数值、数学符号、否定词和常见数学结论的差异。不能以重复次数推断答案正确，结果始终待人工核对。
- 找不到可用重复回答时，使用已选择的 AI 通道生成简短草稿。沿用已有网页版/API配置、提问间隔和人工验证机制。
- 草稿进入“待审答案”，可编辑、保存、打开讨论页核对。仅点击该条“确认发布讨论”才发表，顶部批量按钮不发布讨论。
- 本人已有回复时不重复回复。发布前先持久化未知结果标记；需成功回执及本人新回复同时对应，才能确认已发表。审核中、超时和未知结果保留草稿与防重标记。
- 平台任务点状态与本人参与记录分别核对；已发表但任务点未确认完成时，不冒充任务已完成。

## 已验证

- 重复原文与近似变体、独立作者、短回答、数学差异、忽略空泛打卡与点赞。
- 章节讨论识别、普通讨论的默认完成图标、分页、评论尚未加载时等待、新增讨论不改变旧视频/测验的任务标识。
- 本地完整流程：草稿生成、AI备用分支、待审界面编辑保存、关闭后恢复、逐条确认、回执与本人回复对应、审核未知不重发、批量不发布。
- 隔离软件副本中读取真实章节讨论与评论，成功生成来源可核对的待审草稿，并检查实际界面。首次只读验收拦截了平台发布请求。
- 用户随后明确授权完整真实验收：通过待审页逐条发布入口仅发表一条回复；刷新后确认本人回复正文且只有一条，重新读取该讨论任务点确认为完成。原安装文件与用户数据未改动。
- 实测暴露了原站追加回复不更新作者缓存造成的回执误报，以及讨论使用 `title` 而非视频的 `name` 造成的完成核对失败。已修复成功回执与新回复 ID/正文的对应核对、按讨论唯一 ID 读取任务点、手动发表同步时的完成核对，并加入回归用例。
- 修复后用同一条已发表讨论做只读复核：软件标记完成、不再生成草稿、不重复发表。修复后的即时发布回执分支通过模拟原站“只追加 DOM、不更新作者缓存”的页面验证，未为了测试再发表第二条。

真实 AI 网站的图片与回答链路沿用既有模块，本功能的备用分支通过模拟 AI 回答验证。

## 范围与限制

当前支持学习通新版章节内的 insertbbs → bbscircle → groupweb 讨论页。无法读取、需登录/验证或页面结构不同的内容保留给人工处理。每条讨论最多加载 50 页、2000 条评论；未读完时会在来源处明确标注，只能表示已读取范围内的重复情况。平台限制发表前查看评论时，不绕过限制。
