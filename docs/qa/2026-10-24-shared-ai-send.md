# 两平台共用 AI 通道发送与恢复排查

## 只读安装版诊断

- 两个平台使用同一豆包网页通道，安装版记录存在发送回执未确认、回答归属未确认等阻断；不能把它们直接解释为平台限流。
- 学习通复用已经保存的高可靠答案时，仍会检查旧的全局连续失败计数。没有新 AI 请求也可能被记为限流，反复开始仍然暂停。
- 智慧树另有单选题收到多个选项答案的记录，此时停止回填属于必要的答案校验，不能降低规则强行通过。

## 源码修改

- 被动观察网页自身的正常提问 POST。只有当前标记与本地消息 ID 匹配才确认发送，不等待被折叠的长提示完整出现在 DOM。
- 发送确认与回答归属继续分开：匹配发送并不允许接收历史回答，仍要求对应回复 ID 的完整回执或明确的 DOM 关系。
- 输入、上传、发送、消息归属等本地错误不再积累为限流；真实空回答与网页明确提示的验证、频率限制仍保留保护。
- 正常已保存答案恢复不受旧失败计数阻挡，逐题检查点及待审保持不变。

## 验收与边界

- 用户授权后，使用保留登录的独立验收窗口向豆包发送一张不含个人信息的红色方块图。网站随后要求人工验证，由用户完成；恢复读取的是同一条消息的原回答，未再次发送。
- 该真实流程验证发送、人工验证后恢复、读取原回答；没有处理或提交任何课程作业。不能据此宣称两平台整份真实作业已通过。
- 本地浏览器回归覆盖折叠提示下的准确发送确认、延迟回复绑定、历史回答拒绝、草稿保护与发送不明不重发。
- 学习通实际执行器的匿名三题测试覆盖旧失败计数下的已存答案恢复、仅失败题续问、零提交；其他保护回归另行检查。
- 安装文件和安装版课程、答案、登录数据未修改。中性图、截图、原始记录仅留在被忽略的本地验收目录。本轮源码随 0.6.8 通过隔离发布副本打包。
