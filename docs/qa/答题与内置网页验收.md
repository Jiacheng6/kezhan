# 答题与内置网页修复验收

2026-10-19，0.5.11 发布前源码验收。验收过程未替换用户安装版，未提交真实作业。

## 已实现

- 提交优先处理已存在的确认框，兼容父页面弹窗、隐藏的重复按钮及原生确认；等待平台结果后才记录成功。结果未知时保留草稿，不重复发起提交。
- 手动提交后核对作业标识与平台结果，同步清除待审记录。页面缺少提交按钮本身不算已完成。
- 关闭作业页后可以重新打开并恢复。旧简答编辑器序号按唯一完整题干重新匹配；题目或选项不一致时保留草稿。保存选择题与简答答案后会实际回填并回读。
- 网页列表和标签增加关闭入口；正在执行任务或恢复答案的页面暂时受保护。页面较多时仅清退已保存草稿的空闲待审页面。
- 推广弹窗可自动关闭；人工验证保留。当前题暂停后，点击“验证已完成，继续本题”才续跑，不重新发送。
- 千问排除隐藏编辑器、旧图片和隐藏加载控件；连续相同回答也核对新卡片。DeepSeek 排除隐藏的旧上传进度控件。
- 新增 OpenAI 兼容 API：地址、密钥、模型配置，密钥通过 Windows 加密保存；支持图片请求、手动连接测试和停止取消。答题模型须支持图片输入；未对真实付费服务发起测试。

## 0.5.12 确认提交修复

复现了 1544 与 1260 像素高作业 iframe 中，确认按钮被外层视口裁切、鼠标点击超时的问题。修复会在明确的越界错误后对同一确认按钮使用原生 Enter 激活，不派发 JavaScript 假点击；仍核对平台提交结果。

模拟页面验证激活事件为可信事件且仅触发一次。经用户明确批准，另对一份已有答案的真实作业完成最后确认，学习通返回提交成功，其 3 道题均同步为已提交；没有重新填答，也未修改安装版文件。

## 0.5.13 待审恢复与安装启动修复

修复上次提交结果未知的标记在重启后永久拦截回填的问题。用户单独打开恢复或保存答案时，重新读取平台页面，核对原作业、作答次数、题目与可编辑状态，再恢复草稿；直接重试提交不会解除未知结果保护。

在独立数据中，用当前待审记录及本机加密登录态复现 0.5.12 的拦截，再用修复源码打开真实页面。两道简答题均恢复成功，编辑器正文和表单存储值逐题回读一致，同文“保存并填入”通过。平台写请求被拦截，没有调用提交接口；原安装数据及登录文件的前后 SHA256 均一致。个人记录、页面截图和验收脚本只保存在被忽略的本机测试目录。

本地页面回归覆盖：关闭后未知状态恢复、已有页重新核对、旧简答序号、保存并填入、已提交结果同步、只读/题目变化/作答次数变化时保留保护，以及连续提交不重交。

通过独立 NSIS 测试程序执行与安装器相同的自定义宏，验证更新后的启动目标为新安装的 EXE、已有快捷方式重定向到新位置、已删除快捷方式不被额外创建，以及中文和空格路径。未执行真实安装，尚未在反馈者电脑确认启动失败的确切原因。

## 0.5.14 待审操作入口修复

0.5.13 的独立“打开并核对”入口可以恢复未知提交状态后的草稿，但直接点击“提交这一组”或顶部批量提交会触发重复提交保护，未进入恢复。这次补齐实际操作路径：重新读取待审状态，先恢复需要核对的作业；该次操作不调用提交接口，用户核对后再点击提交。主按钮明确显示“恢复并核对”，已有确认框则在核对后显示“继续确认提交”。

本地拦截页面已验证两个真实 UI 入口，断言恢复期间提交接口请求数与提交动作数均为零，并逐题回读草稿。保留后端未知结果不重交、题目/作答次数变化拦截。修复简答草稿未填入却在汇总计为已填入的问题，已保存但未验证回填的正文继续保留待审。

经用户批准，在其 0.5.13 正在运行的窗口执行“打开并核对”：两道待审简答题正文均在真实页面显示，软件回读验证成功，记录保留待审、已提交总数不变；未提交作业，也未修改安装文件。这验证了独立恢复可用；0.5.14 补齐的主按钮与批量入口另由上述本地 UI 回归覆盖。
