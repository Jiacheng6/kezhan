# 多任务点章节与平台跳过修复

状态：源码修复，尚未打包、发布或替换用户安装版。

## 已确认的问题与修改

- 学习通同一卡片含多个视频时，播放器原先取第一个视频框架，模块记录也存在取第一条附件的路径。现在按附件 objectId、jobid 或唯一名称定位目标；播放、弹题检测及完成回查使用同一视频。目标不唯一时不采用邻项完成标记。
- 讨论题的截图分支会直接拒绝不足 20px 高的题面。改用共用截图降级流程，短题面或零高内容容器仍可尝试截图；不改变讨论草稿待审和发布规则。
- U校园目录中不同位置的 Vocabulary 节点可能同名、同状态。旧去重会合并它们，导致之后的节点状态错位。现在保留独立行，只读同一任务行的状态；数量或名称不匹配时不按错位结果记完成。
- U校园执行前核对该具体必修节点，执行后若教程总数未增长，再核对该节点。已有平台完成标记时可确认完成，不重复学习；没有明确标记仍保留待核对。
- U校园听力教程按名称或实例标识跳过，选课清单显示原因，旧选择在运行阶段也受保护。保留非听力教程的选择题、阅读及翻译任务。
- WeLearn 已知本人任务直接跳过；课件解析后才发现的口语/录音任务同样跳过，保留未完成状态且不写学习或成绩数据。队列继续下一项，跳过不计入完成数。

## 补充：U校园 `context is not a function`

用户反馈日志显示，批量启动后首个学习节点立即抛出该异常，重开一次后原样失败。实际调用链是 `startUcampusTasks → PlatformRuns.start(..., ctx()) → runUcampusStudyNode → readTutorialProgress(context())`：队列传入的是连接对象，旧的学习执行器和进度读取器却仍调用它，因而抛出类型错误。

修复为统一解析连接对象或连接获取函数，扫描、进度读取、目录核对和学习节点均可接受两种入口；答题分派也使用传入的连接，不再另取全局连接。无效连接返回明确提示且不自动重复尝试。运行日志不再把教程总数增长描述为唯一完成依据。

新增 `test-ucampus-context.mjs`，通过拦截页面测试，真实调用学习节点执行器的进度读取、播放器定位、节点执行及回查；对象与函数两种入口、学习通并发、停止、无效连接保护均通过。模块检查 145 项通过。此处的节点学习和进度响应均来自模拟页面，不是用户平台上的真实课程记录。
